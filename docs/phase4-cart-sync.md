# Phase 4AA cart sync foundation
Pure contract only, no network or production changes. Preserve existing local account isolation and checkout's live stock/price validation. Project only product ID, size, color, custom variant ID, add-on flags and quantity. No names/prices/images/stock/gift messages or profile data transferred. Existing cart identity also includes name, price and gift message; duplicate normalized identities or personalized/legacy cart entries deliberately block projection until an explicit migration/resolution exists. Never drop these rows or silently merge them.
A cart revision is a compare-and-set guard, not stock reservation. Server must independently validate product/variant availability and quantity constraints; hydration must use current published catalogue data. Checkout clear candidate requires exact acknowledged revision; never retry a stale clear against a newer cart. For real activation, atomic order ownership/idempotency/receipt verification and per-purchased-line reconciliation are mandatory; no generic client clear RPC. Offline queue, durable mutation IDs if rebasing, explicit conflict UI, guest migration, actual Auth and two-device tests remain.
Wishlist SQL contract passed isolated PostgreSQL 17 with simulated JWT claims, not hosted Auth or concurrent sessions. Do not apply draft SQL to live database.
