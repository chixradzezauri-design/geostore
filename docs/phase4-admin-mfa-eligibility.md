# 4AR — pre-MFA eligibility and effective access bridge
The self-only boolean RPC permits enrollment/challenge routing at AAL1, checks current session owner/expiry, existing owner or active confirmed staff with permission, and never returns role/permissions or grants access. The disabled JS resolver verifies current user, calls eligibility, checks AAL, then independently obtains effective server permissions. It explicitly avoids existing owner shortcut in normalizeAdminAccess. Scope changes discard responses. Tests are isolated/simulated, not real Auth. No App mount or live SQL; shared session coordinator, auth callbacks, fresh-password reauth (may downgrade AAL), safe recovery and real browser/SDK tests remain essential. Existing App owner shortcut remains in currently deployed path, so do not enable server enforcement independently. No automatic factor removal or recovery bypass.
