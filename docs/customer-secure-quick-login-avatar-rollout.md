# Secure quick login & profile avatar rollout

- Stage 01: native password-manager autofill and opt-in credential save when supported; no application password storage. Safari/iOS controls its own save prompt.
- Stage 02: verify locked Supabase JS version, supported Auth passkey feature/configuration and relying-party origin; keep experimental passkeys disabled until an isolated test verifies actual Auth-issued sessions. Device Face ID/PIN are authenticator methods, never local application login checks. Maintain password recovery and existing admin MFA.
- Stage 03: passkey enrollment, sign-in, revocation and recovery testing; no silent enrollment, no raw biometrics or PIN collection.
- Stage 04: selectable 3D-style profile avatar catalog, compact mobile layout and account-scoped persistence with ownership enforcement. No public disclosure of profile identity.
- Stage 05: signed-in, cross-device and responsive verification; one draft PR, no Production changes until approval.

References: https://supabase.com/docs/guides/auth/passkeys and https://developer.mozilla.org/en-US/docs/Web/Security/Authentication/Passkeys.

## Stage 02 implementation
Locked Supabase JS is already 2.109.0 (minimum 2.105.0); no dependency upgrade needed. The native SDK ceremony is wired behind `VITE_CUSTOMER_PASSKEY_ENABLED=true` and the exact HTTPS production origin. Do not set this flag until the Auth server Passkeys toggle and RP ID `geostore.vercel.app`, RP origin `https://geostore.vercel.app`, display name GEOSTORE are verified and an isolated real ceremony is tested. No Production Auth configuration was modified. Browser chooses Face ID, fingerprint, device PIN or security key; the app never handles a PIN. Existing admin permission and MFA logic is unchanged; enrollment is restricted to non-admin customer UI. Next: credential management, secure recovery and real-browser verification. The feature is experimental.

## Stage 03 implementation
Added owner-verified passkey list, rename, confirmed revocation, re-fetch verification, stale-account result suppression, localized device PIN/biometric wording and recovery guidance. Deletion does not revoke current sessions or delete device-side credential storage. No application PIN or password is persisted. The rollout gate remains OFF; no live Auth settings changed. Real enrollment, PIN/biometric sign-in, revoked-key rejection, recovery and account-switch browser tests remain release requirements.

## Stage 04 implementation
60 public original gradient-rendered 3D-style SVG portraits (18 boy, 18 girl, 12 animal, 12 fantasy), eight backgrounds, category filters, preview and account-scoped saved selection using a single non-authoritative Auth user_metadata field. Three original owner-only winter, Black Friday Noir and GEOSTORE Signature portraits are generated by a private server module; the authenticated API validates Supabase Auth user and trusted owner role, returns no-store responses, and never grants authority from user_metadata. Ordinary users cannot fetch exclusive art; injected metadata is normalized to public defaults. These are lightweight 3D-style vector portraits, not animated meshes. Real account cross-device and browser tests remain required. Disabled automatic preview deploys for the current draft branch in repository configuration. No Production or database mutation.

## Stage 05 implementation
Profile-only compact layout, avatar placement, two account shortcuts, readable marketing consent notice, light storefront-compatible purchase analytics, offers, order progress/request cards, notification panel and native password-manager checkbox styling. Existing handlers, account ownership, consent feature flag, order RPCs and security rollout gates unchanged. Final CI and actual authenticated visual testing remain required.

## Stage 06 audit
Private avatar state is remounted on access-scope changes, stale operation generations are ignored, and save now checks a fresh authenticated server read before showing success. Passkey UI prevents local close/mode changes during a credential ceremony. Added disposable Stage78 real-Auth checks for two independent sessions, account isolation, forged owner metadata and preserved admin denial. This is a CI rehearsal, not a live iPhone/Android test. The Passkey rollout remains disabled; production Auth configuration is not exposed by the available connector and has not been modified. Actual WebAuthn enrollment, sign-in, revocation and recovery still need a supported isolated Auth runtime and browser testing before enabling the rollout.

## Stage 07 CI correction
Build check on stage 06 exposed a ReferenceError in the new post-save verification (two failing regression tests). Corrected the Auth reference to use the supplied session client. Existing assertions for persisted values and stale sessions remain intact; rerun CI before release.
