# 4AD staged reconnect journal
Account/collection-scoped one-pending-intent localStorage journal, separate from existing local UI data. Save before a network write and mark uncertain before sending; storage failures block the request. Read server state after reconnect; only exact base/revision allows original CAS retry. Any divergence requires user review, not automatic merge or a blind new revision. Matching data at a newer revision does not prove a prior write succeeded. Clear only after a validated matching RPC acknowledgement or an explicit user resolution. No private gift text or raw product payload. Not an App mount, offline multi-edit queue, or complete background sync. Browser localStorage is not a transactional cross-tab lock; require a single writer coordinator and real two-tab tests before activation. Transport must use the journal's original expected revision atomically, not read a newer revision from UI. UI must show pending/offline/conflict states, revalidate catalogue and account, and preserve existing local data on quota or invalid snapshots. No live changes.
