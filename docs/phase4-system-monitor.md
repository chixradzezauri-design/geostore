# 4AX — privacy-minimized error capture
Browser runtime/resource errors, unhandled rejections, root/admin React render errors produce fixed allowlisted event codes only, minute timestamps and capped counts. Memory ring retains at most 30 buckets for at most 30 minutes; no persistent storage, raw message, stack, request URL, user identifier, credentials, external service or network transmission. Root fallback avoids a blank screen on render errors. Existing admin fallback keeps retry and shows a fixed technical code rather than raw message/stack. This does not sanitize all existing console logging or React/SDK internals. Counts are observations, not unique incidents; root and browser events may overlap. No cross-device history, server ingestion, alert delivery, dashboard or paid service yet. Unit tests cover allowlist, payload exclusion, retention, bounds, clocks and listener disposal. Next: authenticated privacy-preserving aggregation, review abuse limits and admin read access, retention and alerting. Existing 2FA rollout stays disabled despite passing isolated browser fixture; real Auth verification remains a release gate.
