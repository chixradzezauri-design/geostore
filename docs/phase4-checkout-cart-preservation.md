# 4BM — checkout preservation
Existing checkout has server order-ID retry fingerprint and synchronous submit lock; neither is replaced. Quick-buy previously cleared the entire local cart, even though it only ordered a separate product. Now quick-buy preserves it. Normal checkout captures cart at submission, rejects local changes before catalogue reconciliation or sending order, and clears only when current and persisted cart are identical to captured snapshot and validated receipt grouped item identities/quantities match requested items. Otherwise preserves the cart for review (receipt flag), no automatic resubmission. No blind subtraction or remote clear. This is conservative: changed metadata or storage unavailability may retain purchased lines and require user review; actual confirmation UI copy and cross-tab atomic writes need further integration. Existing fingerprint idempotency is same-payload/same-tab, not global cross-device deduplication. Remote cart checkout reconciliation still requires server-owned receipt binding and idempotent CAS transaction, real two-device tests. No server migration or production deployment.
