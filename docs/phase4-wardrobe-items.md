# 4AG wardrobe metadata and storage test draft
A per-account private metadata snapshot holds only item UUID, limited text fields and nullable owner-scoped private photo path; no public URL, raw image or legacy auto-import. CAS change/remove; stale replay cannot resurrect deleted metadata. Referenced object must already exist in the designated private bucket. Photo deletion deliberately not exposed; metadata deletion is not physical file deletion. Existing customer data untouched.
CI adds isolated PostgreSQL fixture with simulated JWT claims and intentionally broad existing Storage policy; validates restrictive isolation, immutable files, malformed paths, other bucket compatibility, metadata CAS and account cascade. It is not actual Storage API testing. Before rollout require real Auth and Storage integration, owner-controlled physical erasure, quota/rate limits, orphan handling, full image validation, private cache behavior, local legacy recovery and UI. No live migration or bucket provisioning.
