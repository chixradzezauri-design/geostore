# 4BB — opt-in refresh, global write budget and independent retention
Monitoring panel supports user-controlled two-minute refresh (off by default), visible document only, no overlapping requests, no catch-up or retries, last successful refresh time. Stops on unmount and retains existing owner/2FA release gates. SQL candidate limits accepted observations globally to 30 per server minute across instances, uses a singleton private budget and nonblocking transaction advisory lock. Over-budget/busy reports fail without mutation; counts remain sampled and may understate incidents. This bounds accepted writes, not incoming request volume or API invocation costs; external request abuse still needs verification. Private owner-only pruning routine allows cleanup even without new writes. Schedule only after release review (proposed daily using existing pg_cron if available; not installed or scheduled here). No hosted SQL, configuration changes, or paid services. Tests cover budget, reset, retention, ACL and refresh behavior; CI required.
