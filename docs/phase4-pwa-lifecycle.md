# 4BF — non-disruptive updates and connection hints
App renders localized inline connectivity/update notices only when relevant. Browser online status is a hint, not proof of service reachability. Worker waiting state is observed only with an existing controller; initial installation is not mislabeled as an update. Existing tabs retain active release; no skipWaiting, clients.claim, background order resend, auto reload or storage of private data. Registration after load notifies observer, and subscriptions clean up on unmount. Actual built worker integration test uses isolated loopback HTTP fixture: only offline file cached, simulated network failure, API failure without cached response, reconnect, second worker remains waiting. Chromium fixture plus unit tests; native iPhone/Android and Vercel routing/headers still require release verification. No runtime asset cache added because offline catalogue/pricing/auth safety is more important than speculative speed gains. No preview/deploy.
