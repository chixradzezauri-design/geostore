# 4BQ — pending wardrobe recovery and quota visibility
Adds owner-only read-only RPC for current metadata snapshot, reserved photo count, pending erasure count and one owner-scoped photo state. No paths enumerated. Existing upload/removal marker is parsed strictly. Only observed intended account state with a newer revision can be explicitly acknowledged, after re-reading under the same Web Lock and matching proof; no server mutation or auto retry. Observed is not proof of original RPC acknowledgement; user reviews actual items. Unknown/reserved or unreferenced uploaded files remain blocked; do not infer deletion or release quota. UI displays 20 reservation limit and pending deletion count. SQL draft, isolated fixture and two JS tests. Orphan retirement, missing-file reconciliation, late upload races, worker scheduling and actual Storage deletion still require verification. No live migration, enablement or deployment.
