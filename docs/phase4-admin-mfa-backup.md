# 4AU — backup authenticator and recovery procedure
Dormant add-only panel in Georgian/English/Russian, mounted only in effective admin view when compile-time rollout flag is true. Requires existing verified TOTP, current AAL2, server-derived permissions, shared auth lock and same owner/epoch. New factor uses separate native Supabase enrollment and verification; only confirmed fresh list indicates readiness. No secret persisted, no automated factor deletion or bypass, duplicate/unfinished enrollments blocked. Use independent device and test login before enforcement. If one factor is lost, use another verified factor. If all factors are lost, password reset alone cannot grant admin access; use documented authorized out-of-band owner identity verification and provider-level recovery review. No implemented all-factors-lost automated recovery; no claim of guaranteed recovery. Before rollout rehearse lost-device recovery and factor revocation, stale token/session semantics, real Auth events, SDK and browser compatibility. Mock tests only; no factor change or deployment.
