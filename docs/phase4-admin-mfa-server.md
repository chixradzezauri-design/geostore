# 4AN — partial admin AAL2 enforcement draft
Read-only production schema inspection confirmed public invoker wrappers and private has_staff_permission/get_my_admin_access, and private require_purchase_owner. Also identified independent inline owner checks in flash sales, order reactivation/reopening, activity logs, visual design and marketing, plus inventory/supplier routines not fully enumerated by admin-name search. Central staff helper protects many but not all RPCs/RLS; do not claim complete coverage. The draft preserves the existing permission checks and adds a signed JWT AAL2 prerequisite for the two private permission functions and purchase-owner guard. Customer-specific policies, storefront reads and current production unaffected. Isolated fixture tests owner/staff AAL1 denial, AAL2 only with existing authorization, role boundaries, unconfirmed/inactive staff, editable metadata, anonymous and missing claims. No live migration.
Release blockers: enumerate all admin RPC overloads, indirect helpers, RLS and service-role Edge/API endpoints; protect each without preventing customers' own operations. Separate safe pre-MFA eligibility endpoint is required because effective admin access becomes empty at AAL1; eliminate App owner shortcut for effective permissions; mount MFA UI with coordinated auth lifecycle; actual Auth AAL2, owner recovery/backup and rollback rehearsal; verify current function definitions/ACLs and schema permissions before release. Never enforce until owner enrollment verified. Existing JWT revocation and stale factor state need additional session/factor checks. No owner or staff account changed.
